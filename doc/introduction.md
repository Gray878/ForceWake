# 不许睡强制闹钟 App 功能需求文档

## 基本信息

| 属性 | 描述 |
|------|------|
| 项目名称 | 不许睡 (No Sleeping Allowed) |
| 项目目标 | 打造一款强制性、高效率的起床闹钟应用，通过任务机制和防作弊措施，确保用户彻底清醒并完成任务才能关闭闹铃。 |
| 开发平台 | 鸿蒙原生 (HarmonyOS Native) |
| 开发语言 | ArkTS |
| 参考应用 | 使命闹钟 |

---

## 1. 闹钟管理模块 (Alarm Management)

| ID | 功能需求名称 | 详细描述 | 优先级 |
|----|---------------|-----------|---------|
| FR-A01 | 闹钟列表展示 | 显示所有已设置的闹钟，包括时间、重复周期、任务绑定状态和开关状态。顶部显示距离下次响铃的时间。 | P1 |
| FR-A02 | 新增与编辑闹钟 | 提供时间滚轮选择器（时/分）、单次/重复周期（周一至周日多选）、闹钟名称/标签、音量设置、震动开关、以及任务绑定功能。 | P1 |
| FR-A03 | 闹钟状态切换 | 用户可以通过列表页的开关快速启用或禁用任一闹钟。 | P1 |
| FR-A04 | 删除与暂停 | 支持左滑或长按删除闹钟。闹钟响起后，任务完成前不允许“小睡”（Snooze），体现“不许睡”的强制性。 | P1 |
| FR-A05 | 铃声和震动 | 允许用户从内置铃声库中选择闹铃声音。提供自定义音量调节和震动开关。 | P2 |

---

## 2. 强制任务系统 (Mandatory Mission System)

> 核心要求：闹钟响铃时，用户必须完成绑定的任务，否则闹铃将持续以最大音量响铃（或音量逐渐增大）。

| ID | 功能需求名称 | 详细描述 | 优先级 |
|----|---------------|-----------|---------|
| FR-B01 | 任务选择界面 | 提供任务分类列表，支持选择和绑定一个或多个任务到单个闹钟。 | P1 |
| FR-B02 | 数学题任务 | 用户需在规定时间内，正确解答设置数量和难度的四则运算题（例如：简单/中等/困难）。 | P1 |
| FR-B03 | 记忆游戏任务 | 用户需完成一个基于卡片匹配的记忆游戏（如翻转卡片找到配对）。可设置匹配对数作为难度。 | P1 |
| FR-B04 | 条形码/二维码任务 | 用户需使用摄像头扫描预先保存的条形码或二维码，用于将用户带离床铺（如贴在厨房或卫生间）。需调用相机及扫码能力。 | P1 |
| FR-B05 | 拍照任务 | 用户需拍摄与预设图片相似的场景照片（如设置时拍摄洗手间照片，闹铃时需再次拍摄）。需调用相机及图像识别能力（简单匹配）。 | P1 |
| FR-B06 | 摇晃任务 | 用户需剧烈摇晃设备，达到预设的次数或加速度阈值。可设置摇晃的难度/次数。 | P2 |
| FR-B07 | 任务配置 | 每个任务都应提供难度或数量设置（如数学题数量、记忆游戏配对数、摇晃次数）。 | P1 |

---

## 3. 强制唤醒机制与设置 (Mandatory Wake-up & Settings)

| ID | 功能需求名称 | 详细描述 | 优先级 |
|----|----------------|-----------|---------|
| FR-C01 | 阻止关机/强停 | 防作弊功能。闹钟响铃且任务未完成期间，需申请鸿蒙系统高级权限，阻止或提升关机、重启、强制停止等操作难度。提示用户此权限的必要性。 | P1 |
| FR-C02 | 常驻后台提醒 | 闹钟需常驻后台，确保任何情况下（应用被清理、设备休眠等）都能准时响铃。使用鸿蒙持久化机制与定时服务。 | P1 |
| FR-C03 | 权限管理 | 集中管理后台运行、悬浮窗、阻止关机、摄像头、存储等权限。 | P1 |
| FR-C04 | 通用设置 | 提供默认任务难度、主题颜色（深色/浅色模式）、音量渐强等常规设置。 | P2 |

---

## 4. 附加与数据模块 (Additional & Data Modules)

| ID | 功能需求名称 | 详细描述 | 优先级 |
|----|----------------|-----------|---------|
| FR-D01 | 起床得分 | 根据任务完成速度、准时程度和任务难度计算“起床得分”，用于激励用户。 | P2 |
| FR-D02 | 早晨感觉记录 | 完成任务后可记录当天早晨的感觉（如：笑脸、悲伤等表情）。 | P3 |
| FR-D03 | 睡眠提醒 | 提供睡眠时间提醒功能，用户可设置提醒时间，到点后通知准备睡觉。 | P3 |
| FR-D04 | 数据报告 | 汇总用户起床时间、起床得分、任务完成统计等数据，生成可视化报告（不作为主模块）。 | P3 |
| FR-D05 | 问题反馈与关于 | 提供反馈入口和应用版本、开发者信息等“关于我们”页面。 | P2 |

---

## 5. 技术要求 (Technical Requirements)

| ID | 技术要求名称 | 详细描述 |
|----|----------------|-----------|
| TR-01 | ArkTS 组件开发 | 界面全部采用 ArkTS 声明式开发范式，确保性能和用户体验。 |
| TR-02 | 持久化服务 | 闹钟数据、设置和任务状态需使用 ArkTS 持久化能力（如 Preference/数据库）。 |
| TR-03 | 系统级权限 | 研究鸿蒙后台运行、定时器及防止应用被强制关闭或设备关机的系统级权限和 API，以实现 FR-C01。 |
| TR-04 | 跨平台兼容性 | 考虑在不同 HarmonyOS 设备（手机、平板）上的响应式布局。 |
| TR-05 | 相机与传感器 | 调用鸿蒙 Camera API 实现拍照、扫码，调用传感器 API 实现摇晃检测。 |

---

## 6. 界面与导航模块 (UI & Navigation)

| ID | 功能需求名称 | 详细描述 | 优先级 |
|----|----------------|-----------|---------|
| FR-F01 | 底部导航栏 | 应用主界面应包含固定底部导航栏，用于快速切换主要模块。 | P1 |
| FR-F02 | 导航栏项目 | 导航栏包含以下 4 个标签：<br>1. 闹钟 (Alarm)：闹钟列表管理（FR-A01）<br>2. 睡眠 (Sleep)：睡眠提醒与追踪（FR-D03）<br>3. 早上 (Morning)：起床得分与感觉记录（FR-D01/FR-D02）<br>4. 设置 (Settings)：应用配置与权限管理（FR-C03/FR-C04） | P1 |
| FR-F03 | 选中状态指示 | 当前激活的标签页应有明显视觉指示（如图标高亮、文字加粗）。 | P1 |

---

### 优先级定义
- **P1（核心功能）**：必须实现，否则应用无法达成基本目标（强制唤醒）。  
- **P2（重要功能）**：增强体验与个性化。  
- **P3（附加功能）**：提升可玩性与数据反馈。
